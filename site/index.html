Architecture

Multi-layer defense & decoupled execution

Third-party code is strictly adversarial. Core applications get no exemption. Host IPC, file access, and background runtimes are separated into deterministic, hardened trust boundaries.

Boundary 1

App UI Sandbox (WebContentsView)

  • ✓ Origin: app://<app-id>/ (Isolated partition)
  • ✓ Node.js: Disabled (Context isolation enforced)
  • ✓ Network: Declared hosts only (CSP cancellation)
  • ✓ Cross-app fetches: Refused (Different origins)
Boundary 2

Backend Process (utilityProcess)

  • ✓ Filesystem: Read-only to app's own folder
  • ✓ Child Processes: Blocked via Node Permission Model
  • ✓ Host Environment: Not inherited (clean env)
  • ✓ Lifecycle: Spawned on first call, stopped idle (60s)

Security Guarantees

Formal platform boundaries & contracts

Every guarantee is proven by test/e2e/hostile.test.js in automated continuous integration.

Boundary Mechanism Adversarial Resistance
UI Layer Sandboxed WebContentsView on origin app://<id>/ with session partition Node access zeroed, cross-origin cookies & local storage isolated
File Serving Protocol handler resolves symlinks and serves only the app's directory + SDK stub Path traversal outside app folder strictly returns 404
Network Declarative allowlist in capabilities.network; CSP mirrored dynamically Undeclared HTTP/WebSocket connections unconditionally aborted
Backend Process utilityProcess constrained by Node Permission Model (--permission) Read-only app directory; zero child_process or worker threads
Identity Access Host signs 5-minute Ed25519 JWTs with audience app:<id> Apps cannot impersonate peers; credentials never touch client apps
Widget Rendering Pure JSON descriptor schema (widget.schema.json) rendered natively by shell Zero third-party JavaScript or HTML injected on the dashboard
Workflow

Ship apps independently in 3 steps

No centralized app review bottlenecks. No heavyweight Electron bundling per app.

01

Scaffold in seconds

Run appshell create. Get a ready-to-code project with UI entrypoint, utility backend, and dashboard widget bindings.

02

Tag & Release via CI

Push a git tag like v1.0.0. Automated CI builds the regular tarball, hashes it with SHA-256, and updates catalog records.

03

Install with Consent

Click Install in the web store. The shell prompts the user, verifies cryptographic integrity, and launches the app inside its private sandbox.

Consent Gate

Install from the web, confirm in the shell

The web store initiates an install request via the registered OS deep-link protocol (appshellcatalog://).

The desktop shell halts execution and displays the package origin, publisher, and permissions. Downloads proceed only after explicit user confirmation. Rollback and updates are 1-click and instantaneous.

Developer CLI

Everything developers need in one binary

No boilerplate required. The Appshell CLI scaffolds, tests in live hot-reloading dev hosts, and packages verified tarballs ready for distribution.

Terminal
# 1. Create a new sandboxed app
pnpm appshell create ../my-app --id my-app --title "My App"

# 2. Run in live dev shell
pnpm appshell dev ../my-app

# 3. Package and calculate SHA-256
pnpm appshell package ../my-app

Multi-Tenant Configuration

White-label & brand your desktop product

A product is defined by a single configuration file (product.json). Configure custom names, deep-link protocol schemes, pre-bundled core apps, and security policies.

products/appshell/product.json schema v1 
{
  "name": "Appshell",
  "protocol": "appshell",
  "dataDirectory": "appshell",
  "package": { "extension": ".appshell", "displayName": "Appshell App" },
  "catalog": "https://samuelek25k.github.io/appshell-apps/index.json",
  "policy": {
    "capabilities": "enforce",
    "allowedSources": ["https://github.com/samuelek25k/"]
  }
}
