One desktop shell. Many apps, delivered independently.

Appshell is a desktop platform on Electron. Teams build apps in their own repositories and release them by tag. Users install them from a catalog into one governed shell, without reinstalling anything.

How it works

  1. Build

    appshell create scaffolds an app with a UI, a sandboxed backend and a dashboard widget. appshell dev runs it in a development shell.

  2. Release

    Tag <app>-v1.2.0. CI packages the app, publishes a release and records its version, commit and SHA-256 in the catalog.

  3. Install

    Users click Install in the store or the shell. The shell asks first, then checks the source, digest and manifest before the app goes live.

Install from the store, confirm in the shell

The store's Install button hands the app's id to the desktop app. The shell shows what will be installed and from where, and downloads nothing until the user agrees. Updates and one-step rollback are on the same screen.

Secure by design

  • Every app isolated

    Each app runs sandboxed on its own origin and storage, with no Node access. Its backend can read only its own folder.

  • Verified packages

    Installs must match the catalog's SHA-256, come from an allowed source and contain only regular files.

  • Declared capabilities

    Network hosts, notifications, secrets and identity are declared in the manifest and checked on every call.

  • Identity, not credentials

    Apps get 5-minute tokens signed by the shell for that app alone. They never see the user's credentials.

  • Widgets as data

    Apps describe widgets in JSON and the shell draws them, so no app code runs on the dashboard.

  • Tested against a hostile app

    Every change runs an app that tries 21 ways to escape, on Windows, macOS and Linux.

Build an app

pnpm appshell create ../my-app --id my-app
pnpm appshell dev ../my-app
pnpm appshell package ../my-app

The app talks to the shell through a small SDK: storage, secrets, notifications, widgets, identity and its own backend.

Make it your product

A product is one configuration file: its name, deep-link protocol, data folder, package format, pre-installed apps and policy. Appshell is the default product; each tenant can have its own.

{
  "name": "Appshell",
  "protocol": "appshell",
  "package": { "extension": ".appshell", "displayName": "Appshell App" },
  "catalog": "https://…/index.json",
  "policy": { "capabilities": "enforce", "allowedSources": ["https://github.com/your-org/"] }
}
