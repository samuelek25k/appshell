Architecture

Built with zero trust — so you can build with total peace of mind.

In Appshell, every app is treated as untrusted by default. Host resources, background runtimes, and local storage stay in strictly isolated sandboxes with zero cross-app visibility.

Boundary 1

Sandboxed UI View

  • ✓ Runs on its own origin: app://<app-id>/
  • ✓ No Node.js integration inside browser contexts
  • ✓ Can only talk to APIs declared in its manifest
  • ✓ Cannot peek at other apps or shared cookies
Boundary 2

Isolated Utility Worker

  • ✓ Reads only files inside its own directory
  • ✓ Cannot spawn child processes or worker threads
  • ✓ Does not inherit host environment variables
  • ✓ Starts on first call, auto-stops after 60s idle

Security Guarantees

Real security, tested on every commit

We never document a guarantee that isn't enforced by code and proven by our automated test suite (test/e2e/hostile.test.js).

Boundary How It's Enforced What It Protects You From
User Interface Sandboxed view on dedicated origin app://<id>/ No Node.js access in browsers, private cookies and storage
File Access Custom protocol serves only files inside the app's own directory Directory traversal attempts outside the app folder instantly 404
Network Traffic Explicit allowlist in manifest; CSP blocks all unlisted domains Apps can't quietly phone home or leak telemetry unless allowed
Background Node Node Permission Model locks the utility process to read-only folder access Backends cannot execute shell scripts or fork unauthorized workers
Identity Access Host mints 5-minute Ed25519 tokens scoped specifically to app:<id> Proves who you are without ever exposing your user credentials
Dashboard Widgets Apps send plain JSON descriptors; the shell handles all the rendering Zero third-party JavaScript running on your home dashboard
Workflow

Ship apps independently in three steps

No centralized app store review queues. No heavy 150MB Electron builds for every tool.

01

Scaffold in seconds

Run appshell create. You get a clean starter project with a UI entrypoint, utility backend, and dashboard widget bindings ready to go.

02

Tag to release

Push a git tag like v1.0.0. Automated GitHub Actions packages your app, verifies the SHA-256 checksum, and updates catalog records.

03

Install with consent

Users click Install in the web store. The shell prompts for confirmation, verifies cryptographic integrity, and runs the app isolated.

Consent Gate

Install from the web, confirm on your terms

Clicking Install in the web store sends a deep link to your desktop app (appshellcatalog://).

The desktop shell pauses and shows you exactly who made the app, what permissions it asks for, and where it's coming from. Nothing downloads until you click Install. Updates and one-click rollbacks happen right on your dashboard.

Developer CLI

Everything you need to build, test, and ship

One lightweight CLI scaffolds new projects, spins up live hot-reloading dev hosts, and packages verified tarballs ready for distribution.

Terminal
# 1. Create a new sandboxed app
pnpm appshell create ../my-app --id my-app --title "My App"

# 2. Test in the live development shell
pnpm appshell dev ../my-app

# 3. Package and calculate the SHA-256 hash
pnpm appshell package ../my-app

Custom Products

Brand it for your organization

A single JSON file (product.json) defines your entire platform. Configure custom names, deep-link protocol schemes, pre-bundled core apps, and security policies for your team.

products/appshell/product.json schema v1 
{
  "name": "Appshell",
  "protocol": "appshell",
  "dataDirectory": "appshell",
  "package": { "extension": ".appshell", "displayName": "Appshell App" },
  "catalog": "https://samuelek25k.github.io/appshell-apps/index.json",
  "policy": {
    "capabilities": "enforce",
    "allowedSources": ["https://github.com/samuelek25k/"]
  }
}
